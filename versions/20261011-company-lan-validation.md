增加 `IP-CIDR,172.29.216.0/24,CORP-WINDOWS,no-resolve`，放在通用 `172.16.0.0/12,DIRECT` 之前。不向 skip-proxy / bypass-tun 添加该网段。

主配置已归档，执行 sync_clash.py 生成公司规则集。确认新增规则只进入公司 provider，Claude/Anthropic 的代理规则保持不变。

使用本机真实 Mihomo 和临时监听端口，加载生成的公司 provider，将其他未命中请求设为 REJECT：请求目标报告返回 HTTP 200，耗时约 0.54 秒；日志确认 `match RuleSet(company) using CORP-WINDOWS`。测试核心已退出，临时文件已清理。

首轮隔离验证因直接引用测试目录之外的 provider 未能启动；改为复制已生成文件到隔离目录后验证通过，不修改正式 provider 或现有应用设置。

## 边界

没有扫描整个网段，不能据此宣称所有主机、端口均可访问。该网段以外的公司网段尚未确认；不扩大到全部 RFC1918 私网。公司电脑离线、隧道故障、地址变化、本地网段冲突或服务权限仍会影响访问。

没有修改 Shadowrocket 运行数据库，也没有声称其 GUI 已加载新规则。发布后需在 Shadowrocket 更新该配置并重新加载；Clash 工作版通过统一更新入口带 --work 更新，再重新选择订阅。默认非 work 不加载公司 provider。
